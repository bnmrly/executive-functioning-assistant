# Commit messages

- Keep commit titles and descriptions generic and focused on the technical change.
- Do not include the dashboard's personal name in commit messages or suggested commit names.
- Use terms such as “dashboard”, “Android app”, and “calendar integration”.

# Permission requests

- Identify foreseeable approvals up front. Finish the preparation that can be done without approval, then group related actions and commands into one approval request wherever the tooling allows.
- Do not ask again for an action already authorized. Request further approval only if a new requirement arises that could not reasonably have been included, and explain what changed.
